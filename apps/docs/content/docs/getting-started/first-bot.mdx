## Before you begin

Confirm that at least one engine is available in the model picker. If every engine is dimmed, finish the provider's CLI sign-in and restart OpenMausBot.

### 1. Create a bot

Use the add button in the sidebar, give the bot a clear name, and describe the role you want it to play.

### 2. Pick an engine and model

Open the model picker in the conversation header. Choose an available provider and model. You can change this later without creating another bot.

### 3. Decide where it can work

Start with no computer for research and coding on your local workspace. Choose a computer only when the task needs a desktop, browser, or isolated environment.

### 4. Send a concrete task

Include the outcome, relevant files or services, and any constraints. OpenMausBot streams progress and shows approvals or questions in the chat.

## A good first message

```text
Review this repository, explain its architecture in plain language,
and list the three highest-impact improvements. Do not edit anything yet.
```

This tests model access, streaming, workspace visibility, and approval behavior without making changes.

## Add more capability later

- [Connect apps](../connected-apps/index.mdx) when the bot needs Gmail, Slack, GitHub, Notion, or another service.
- [Choose a computer](../computers/index.mdx) when it needs a browser or desktop.
- Create a room when several specialized bots should work together.
- Turn a repeatable request into a routine or webhook trigger.
